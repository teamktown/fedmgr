Trust Fabric — Coverage & Roadmap

A pressure-test of where the trust fabric stands and what to build next. Companion to the interactive architecture diagram and the full markdown.

The four planes

peer of data
Identity
Inbound OAuth/OIDC sign-in (GitHub, Google, Okta, Entra). Not OpenID Federation. Required for HTTP/SSE; skipped for local stdio.
runtime · PEP
Data — waypoint
OAuth in, OIDF out: gates downstream MCPs by accepted-anchor + VALID chain; exposes only trusted tools.
source of truth
Control — fedmgr
Owns trust topology (TAs, MCPs, endpoints) via the registry. Sign it; waypoint consumes & drift-checks it.
distribution
Pedigree — letsfederate.org
Signs the fedmgr/waypoint code you run (cosign + SBOM + OIDF mark) — independent of your runtime CA.
Finalized scope: waypoint HTTP/SSE + OAuth edge auth (the identity plane)

The pivot insight: signing into waypoint is plain OAuth/OIDC — not OpenID Federation. The moment waypoint turns downstream it becomes OpenID Federation (chain validation + trust marks). So the cloud/web capability is one bundle: a remote transport (Streamable HTTP/SSE) + an OAuth edge (reuse the GitHub/token-exchange bones in src/fedmgr). Inbound = identity; outbound = federation; waypoint is the boundary.

Open decisions

  • Trust default: self-host your own CA (primary, agency) + optionally trust.letsfederate.org as the code-pedigree signer (secondary).
  • Identity providers: GitHub first (base example); design the edge for generic OIDC (Google/Okta/Entra) from day one.
  • Enforcement tiers: observe → guardrail → enforce → ironhand — operator-selected; honest that it's bypassable until clients embed the obligation.
  • waypoint stays a view over fedmgr's signed registry — never a second registry.

Overall fabric ≈ 45–50%. Trust mechanics are strong and lab-proven; delivery surfaces (cloud transport, identity edge, hosted service, revocation/audit) are the work ahead. Items 1–2 gate the cloud priority.
