OpenID Federation for MCP · deep audit · 2026‑07‑04
Summary Questions Tests Recommendations Trust gaps Use cases Doc prune Next

Strong proof‑of‑concept. Two things block adoption: credibility and enforced pedigree.

fedmgr is an architecturally sound OpenID‑Federation trust backplane for MCP — clean layering (KMS → TA/TMI → MCP → Waypoint), fail‑closed admission, comprehensive SSRF defense, 156 real hermetic tests. But a project selling trust currently ships a headline npm test that fakes success, an ambiguous "what do I install" story, two coexisting architectures, and a "code pedigree" promise that is demonstrated but not enforced. Fix the credibility gaps (cheap) and close the pedigree loop (the flagship feature) and this becomes genuinely adoptable.

End‑to‑end trust flow: enroll (proof‑of‑key, origin‑bound) → TA signs subordinate statement → TMI issues digest‑bound trust mark → verifier walks the chain to the anchor (validateTrustChain) → validate_mcp_invocation checks signatures of subordinate + entity + invocation token, that aud includes the endpoint, and that the required trust mark is present. Clean DAG, no circular deps.

The npm story is broken/ambiguous. Root package.json is name:"fedmgr" v1.0.0 with main:"index.js" — but index.js does not exist. There are two "fedmgr" libraries: the legacy @letsfederate/fedmgr (built from src/fedmgr/, what Dockerfile.fedmgr installs and runs) and the maintained @letsfederate/fedmgr-cli (packages/fedmgr-cli). An adopter typing npm i @letsfederate/fedmgr gets the old monolith. → Q1.

▶🧪 Test run — results & the harness problem

The headline npm test is theater. scripts/run_tests.sh reports Total tests: 4 — it counts four categories (unit/integration/e2e/security), each a jest run against a separate legacy scripts/tests/ tree (14 files), and prints a green ✓. ▶🔐 Trust & code‑pedigree gap analysis

Verifiable end‑to‑end today
  • OIDF chain verification (ES256, authority_hints walk, jose signature checks)
  • SSRF defense (assertSafeUrl, consolidated in kms)
  • Trust‑mark JWS signature + expiry
  • MCP invocation verdict: subordinate + entity + invocation signatures, aud⊇endpoint, required mark present
  • Proof‑of‑key enrollment with origin binding
Aspirational / demo‑only
  • Container digest ↔ running code — bound in the mark, never enforced
  • Revocation kill‑switch — endpoint exists, never queried, in‑memory
  • Key rotation — no revocation signaling on JWKS
  • SLSA/in‑toto provenance & SBOM — generated, never validated
  • Runtime attestation — absent

Verdict: the trust architecture is sound; the trust operations — continuous validation, revocation propagation, runtime attestation — are incomplete. "Code pedigree" is currently a signed decoration, not an enforced guarantee.

▶🐳 Docker & demo assessment

The trust lab is exemplary. ./examples/lab/up.sh is a genuine one‑command experience (generates keys via a step‑cli image, builds TA+TMI+registry, waits for health), and round-trip.sh preflights docker/cosign/syft/jq and aborts rather than faking a result. TA/TMI Dockerfiles are model citizens: node:22-slim, multi‑stage, non‑root, fetch‑based healthchecks.

Where it falls down

  • Root compose is legacy & fragile. Builds federation‑admin + mcp‑core + openbao; requires scripts/setup.sh, prebuilt tarballs, keys, and GitHub OAuth first. Bare docker-compose up → opaque "keys not found", exit 1. No README.
  • Floating base images. Dockerfile.fedmgr/federation-admin/mcp-core/token-exchange use node:current-alpine3.21 → non‑reproducible day‑to‑day. Dockerfile.fedmgr is single‑stage, unpruned, runs as root.
  • Broken healthcheck. federation-admin's HEALTHCHECK calls wget, which isn't installed in the image.
  • Unpinned public images (registry:2, step-cli:latest, openbao:latest); no digest pinning. .env.example ships OPENBAO_TOKEN=dev-only-root-token.
  • Orphaned scripts: validate-infrastructure.sh (self‑notes "OIDC mock deprecated"), bootstrap-federation.sh, enhanced-conformance.sh (no integration point).

All of this rolls up into R11 and the legacy‑removal decision Q2 / R3.

▶💥 Where we fall down (blunt)

  • A product that sells trust ships a headline test command that manufactures a green checkmark and hides the 156 real tests.
  • The obvious install name (@letsfederate/fedmgr) resolves to legacy dead code; the root package's main doesn't even exist.
  • Two architectures and two demo stacks run side by side — readers can't tell which is real.
  • "Code pedigree" is demonstrated, not enforced — the container digest is decorative at verification time.
  • Revocation is a kill‑switch nobody pulls (never queried, lost on restart).
  • Trust is enforced only if the MCP server volunteers to call the verdict tool — no gate by default.
  • You can't run it off localhost without editing code, and can't scale past SQLite.

None of these are architectural dead‑ends — they're finishing work and clarity. The bones are good; the promises just aren't paid off yet.
