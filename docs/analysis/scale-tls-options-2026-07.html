Options A–H: escaping localhost without breaking the laptop

Constraints this holds simultaneously: tens of thousands of dev laptops running the compose lab locally; https identities so shared entities never re-mint; internal http endpoints that will always exist; and airgapped postures (FedRAMP · FISMA · 21 CFR 11). Pick the axes below and compare — the decision is deliberately still open.

Two reframes that changed the board. (1) The OIDF chain is self-authenticating — signed JWTs verified against pinned anchors — so TLS is transport hygiene, not the trust root: identity (a stable https:// URL) and location (where statements are fetched) are separable, which is exactly what the spec's §8 Resolver formalizes. (2) Laptop labs should be disposable trust universes — re-minting locally is up.sh; only shared identities (org anchors, published MCPs, the trustmarket) need to never re-mint.

Blindspots this analysis surfaced

  • NODE_ENV=development is the wrong shape, not just retire-able — global, overloaded, and destined to be baked into prod images by copy-paste at 10k devs. Option G is a correctness fix regardless of TLS strategy.
  • FIPS is a KeyProvider problem (good news) — Node's OpenSSL isn't FIPS-validated; signing via the existing KeyProvider seam into OpenBao/cloud KMS/HSM puts crypto inside a validated boundary. The abstraction is accidentally the FIPS strategy.
  • Revocation is online-only today — /trust-mark-status needs a live call: a scale hot-spot and an airgap impossibility. Signed, time-boxed status artifacts (CRL-style) are missing.
  • CFR 11 is about the audit trail, not the crypto — a mutable SQLite audit_log ≠ tamper-evidence, attribution, retention, trusted timestamps.
  • Airgapped clocks drift and our trust is time-based — short TTLs + drifted enclave clocks = spontaneous outage; TTL/tolerance must be posture-configurable, and the bundle needs a time story.
  • Multi-hop chains are untested — org scale means leaf → intermediate → org TA → market anchor; the verifier supports depth 10, the lab has proven one hop.
  • CT-log leakage — public certs publish internal hostnames to transparency logs; B/H avoid it, C accepts it.

Portfolio, not a winner

These aren't mutually exclusive — the audiences differ, so the endgame is a portfolio: A as the shipped laptop default · G immediately (small, corrects a foot-gun) · B/F documented paths for enterprises · C for our hosted anchor · E as the next architectural build · H as E's packaging for the regulated tier.

DECIDED & BUILT (2026-07-12): A + G shipped together, test-first. G: FEDMGR_ALLOW_ORIGINS exact-origin exceptions in the kms SSRF guard + the fedmgr-mcp policy layer (14 new tests). A: Caddy internal CA in the lab (TLS identities https://localhost:9443/9444/9445), root exported to deploy/lab/ca/root.crt, NODE_ENV=development removed from every lab and client config.
