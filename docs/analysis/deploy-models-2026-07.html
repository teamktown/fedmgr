From laptop to K8s-as-a-service

A dev should be able to deploy fedmgr somewhere (a VM, OKE/EKS/AKS) and then just connect to it — MCP over the network — instead of running everything on their laptop. This maps the tiers, what changes at each, and why the key-management upgrade (OpenBao) is sequenced after this analysis: the right vault wiring depends on where the thing runs.

The one structural insight. Almost everything that feels "hard to deploy" today is a single root cause: the lab runs on http://localhost identities, which forces NODE_ENV=development through every URL guard. The moment a deployment has a real DNS name and TLS, entity ids become their production form (https://trust.example.com/…), the dev flags vanish, and the same code runs unmodified — the guards were built for exactly that. Deployment work is therefore mostly origin and transport work, not trust-engine work.

How a remote dev actually connects (the T1/T2 promise)

  • Deploy: operator runs the compose (T1) or terraform apply + helm install (T2). The TA, TMI, registry, and waypoint come up with real origins.
  • Connect: the dev adds ONE remote MCP server — waypoint's /mcp URL — authenticating via the OAuth edge (their IdP: GitHub/Google/Okta). No local checkout, no node, no docker on the laptop.
  • Use: every tool call rides waypoint's admission: policy + §10 chain to the pinned anchor, exactly as verified locally. Enrollment of new MCPs is fedmgr entity config + entity enroll from anywhere (published CLI), pointed at the deployed TA.
  • What must be true first: waypoint HTTP/OAuth mode needs tests (assessment R5 — it is wired but unverified); multi-user session semantics need a decision (one shared waypoint policy vs per-team policies).

The seam is KeyProvider in @letsfederate/kms (kid() · jwks() · signJwt()) — TA, TMI, and the CLI already sign through it. No rung requires touching trust logic; the abstraction predates this analysis and is reused, not reinvented.

Sequencing (and why OpenBao waits)

  • 1. PUBLIC_ORIGIN knob — unblocks T1 today and is a prerequisite for every tier above it (small: compose env + up.sh + CLI defaults).
  • 2. Waypoint HTTP/OAuth verified — tests + one live tunnel session (the T1 "connect from anywhere" proof; R5).
  • 3. OpenBao as a compose service + BaoKeyProvider — now the vault lands in a topology that matches where it will run, and the .pass weakness dies. (This is the "walk" the crawl/walk/run plan called for — doing it before 1–2 would have wired it to localhost assumptions we're about to remove.)
  • 4. Helm chart + Terraform for OKE — T2 becomes real; same images, same KeyProvider, PVC for state, Ingress for origins.
