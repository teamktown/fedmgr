What we're building

Turning fedmgr from two overlapping codebases into one clean, self-verifying trust tool with a single front door. Below: the decisions we locked in, the plan in flight, and how we're keeping it legible to both an AI assistant and a human.

The mission in one line. When an AI assistant reaches for an MCP tool server, it should be able to cryptographically verify that server belongs to a federation you trust — chain of trust TMI → TA, a signed trustmark, an SBOM, and provenance — instead of taking it on faith. fedmgr is the tool that mints, manages, and enforces that trust.

Phase 2 — fedmgr init: mint a trust ecosystem spine shipped

Each step is a fail-fast gate; if it can't be proven, init stops rather than pretend. The spine — the observability core, the init phase runner, and fedmgr doctor — is built (166 tests green). Phases below are wired ✓ or planned.

  1. Validate before run. wired ✓ Hash our own installed files against a shipped manifest; abort on mismatch. (Self-consistency, not authorship — the authorship gap rides npm/sigstore provenance. Arms once the publish pipeline emits the manifest.)
  2. Mint a local CA. wired ✓ Root CA into ~/.letsfederate/ca/ via step-cli, idempotent. --accept-ca <file> to trust a provider CA. Every CA is independently re-verified by Node's X.509 parser (a different tool than the one that made it) or init aborts.
  3. Stand up the minimal ecosystem. wired ✓ Local OCI registry + Trust Anchor + Trustmark Issuer, keys auto-generated (init drives the lab).
  4. Self-provenance demo. wired ✓ SBOM the workspace (321 real components) → sign with cosign → independently verify with Node's crypto (and cross-checked by cosign verify-blob). Push-to-registry + trustmark attestation is the next sub-slice. fedmgr init --no-up runs this as a fast "prove my supply chain" path.
  5. Enforce the SLA. next Run SSC scan-all against waypoint; no trustmark while any HIGH/CRITICAL exists.

Observability — legible to LLM & human built: @letsfederate/obs

  • Dual-format logs. done Syslog-style decorated lines for people, structured JSON for machines/LLMs, one global LOG_LEVEL; logs to stderr so stdout stays machine-clean.
  • OpenTelemetry-friendly. OTel API in the code (near-zero cost, no forced exporter); a heavier collector/Grafana sink stays an opt-in compose profile.
  • Single pane, lightweight. docker compose logs as the floor; our own fedmgr logs / fedmgr doctor console as the default pane — minimal deps, minimal support surface.
  • Mission-aligned traces. Span names map to trust operations: mint-ca · build · sbom · sign · push · trustmark · verify — so an assistant can reason about exactly where trust was established or broke.

How we test — no theatre

  • Independent cross-checks. When one tool produces an artifact, a different tool verifies it. The CA is minted by step and re-verified by Node's own X.509 parser (and spot-checked with openssl) — a green means two implementations agree, not that one function returned.
  • Negative tests. Every checker has a test that feeds it something bad (a non-CA leaf cert) and asserts it's rejected. A rubber-stamp check can't pass those.
  • Honest skips. Docker-gated tests print # SKIP when Docker is absent — reported as skipped, never counted as a pass. We don't manufacture green.
  • Tests are drift detection for you too. npm test doubles as an environment health check: if a tool's output drifts, an independent verifier stops agreeing and the suite fails loudly. 172 tests, 0 fail, 8 honest skips.
